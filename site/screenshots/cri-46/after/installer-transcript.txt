Choose your evaluator models
A separate evaluator reads filtered code without your coding conversation. Codex
and Claude use their signed-in CLI and usage allowance. Pi, Cursor, and OpenCode
need a separate evaluator route. Paid OpenRouter presets use API credits;
choosing one enables paid requests. There is no model-call cap by default; set
one later with sphinx config --max-model-calls. Setup makes no model calls.

  1. Codex · low usage
    GPT-6 Luna for every change size. Uses your Codex sign-in and allowance;
    account access is required. Review size and reasoning effort still scale
    with the change.
  2. Claude Code · low usage
    Haiku for every change size. Uses your Claude CLI sign-in and allowance. The
    haiku alias follows your provider’s available Haiku model; no automatic
    Sonnet or Opus upgrade.
  3. OpenRouter · Haiku 5.5 (experimental, paid)
    Lower-cost option: Haiku 5.5 for every change size, with an 8,192-token
    output ceiling including reasoning. Tests found false rejections of
    sufficient answers; see eval/RESULTS.md. Reference input/output prices per
    1M tokens start at $0.10/$0.50 below 100k input tokens; higher context tiers
    cost more. Uses OpenRouter API credits, not your coding-agent allowance.
  4. OpenRouter · DeepSeek V3.2 (experimental, paid)
    An open-weight alternative for every change size. Synthetic tests found
    question-quality and grading failures; see eval/RESULTS.md. Requires an
    OpenRouter key and credits; billed separately from your coding agent.
  5. OpenRouter · free router (best effort)
    Explicit opt-in to openrouter/free. Requires a key. Model selection varies
    by request, and tool-call failures or rate limits can interrupt checks.
    Sphinx does not switch to a paid route automatically.
  6. Choose by change size
    Set separate provider:model routes for small, medium, and large changes.
