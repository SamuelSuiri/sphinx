# CRI-49 handoff: change scope and question-linked diffs in the browser questionnaire

## What changed
- **`src/change-view.js` (new)**: read-only display model for one frozen checkpoint.
  - Base = `snapshot.base` tree. Head = `snapshot.head` commit (push) or the pinned `snapshot.indexEntries` (commit).
  - The rename-aware `git diff -M --raw/--numstat` is accepted only if every allowed side's blob ID matches those recorded entries, and its path set equals `snapshot.files`. For commit checkpoints it must also be stable across two reads. Otherwise the view is "unavailable", never silently different.
  - Per-file: status (added/modified/deleted/renamed), binary flag, additions/deletions (`null` when unknown, never 0), mode change, and special kinds (symlink/submodule).
  - Diffs are blob-to-blob with context 3/25/all, a 3,000-row display cap (`truncated: {shownRows, totalRows}`), and a 2 MB cap (`too-large`). Notes: `binary`, `rename-only`, `mode-only`, `empty`, `non-utf8`.
  - Excluded files appear only as a count. A rename across an exclusion boundary shows as an add or delete with no counts, so the excluded name never leaks.
  - `evidenceFor(question, review)`: cited paths come from `question.evidence`. Line ranges come **only** from retained observations whose blob IDs match:
    - `read_file`: start/end line.
    - `search`: the matched line.
    - `read_diff` pages: regenerated with the shared `workspaceDiffText` and checked byte-for-byte at the recorded offset.
  - Model-written evidence `reason` text is never exposed, because it can reveal the answer (same rule as concept labels).
- **`src/review-workspace.js`**: extracted `workspaceDiffText()` (the exact text `read_diff` paginates). Reviewer behavior is unchanged.
- **`src/browser-interview.js`**:
  - Loads the view beside each checkpoint (non-blocking; a failure only shows "unavailable").
  - New token-scoped GETs `/change?id=` and `/diff?id=&path=&context=`. Both are bound to the active checkpoint ID (409 otherwise) and revalidate the snapshot first. Unknown or excluded paths return 404.
  - Publishes `state.change` (header and totals) and `state.evidence` ({questionId, refs}).
  - **Display-only publishes keep the actionable `revision`.** Without this, an answer submitted while evidence arrived got a 409; `test/browser-git.test.js` caught it.
  - `publicFields` now passes `event`.
  - Passed message now says it is not a review of every changed line and not a claim that the code is correct.
- **`src/browser-page.js`**:
  - Layout: change header (repository, operation and destination, base→head or staged, totals, excluded count, progress, "checkpoint changes, not necessarily a whole PR"). Desktop columns are 20/45/35: file list (All / Relevant filters, path search, arrow-key navigation), unified diff (old/new numbers, +/− signs, ▸ evidence marker, hunk headers, hidden-line gaps, More context / Full file), and the question pane with "Code behind this question" refs. Below 900px: Question / Files / Diff tabs, with the question first.
  - The first cited hunk opens automatically without switching views. A file the person picked is never replaced.
  - Answer controls only lock `#composer button`; browsing stays available while a check runs.
  - All repository text still enters via `textContent`.
- Docs: `docs/architecture.md` (module table and a questionnaire paragraph), plus one README sentence.

## Tests
- New `test/change-view.test.js` (real temporary repositories): status and totals match `git diff --numstat -M`; later commits and working-tree edits don't change the view; added/deleted/renamed/binary/empty/mode-only/excluded files; truncation; the commit checkpoint refuses a different staged index; evidence ranges (diff page with offset, unchanged dependency, search, rename source mapping to the renamed file, no-observation fallback, forged text/offset/oid ignored, foreign snapshot, no review).
- `test/browser-page.test.js`: harness now creates nodes lazily and supports `setAttribute`/`dataset`/`replaceChildren(...items)`. Four new tests: header and literal paths; draft and question preserved across 3 files, filters, search, context and tabs; evidence link and markers; unavailable fallback.
- `test/browser-interview.test.js`: end-to-end with a real repo: `/change`, `/diff`, 404/409 cases, verified refs in state, no private reasons, and the original revision still accepted after evidence arrives.

## Not done / limits
- No split view (optional) and no draggable pane resizing; the panes are fixed proportions.
- The reviewer's evidence schema is unchanged. Ranges are what the reviewer *read*, not a model-asserted "this exact line". I chose this to avoid unverifiable anchors; a model-supplied range would need a schema change and re-validation.
- Relationship text is omitted on purpose (answer-leak risk).
- Terminal `sphinx check` and native fallback forms still have no change view.
- Landing-page stats belong to CRI-46.
