## Failure
- `test/check-cancellation.test.js` "cancellation while the final grade is in flight…" › EOF: `ENOENT …/fixture-state/grade-terminated`.
- This is a pre-existing flake, not caused by this PR. The same assertion failed on `main` (run 39047558408) and on the CRI-42 and CRI-46 branches, all on macOS. The same commit `d642b11` passed in a parallel run.

## Root cause (test fixture race)
- The stub provider wrote `<phase>-ready` *before* registering its SIGTERM handler. Once the test saw the ready file it cancelled. If the provider was descheduled between the two statements (common on loaded macOS runners), SIGTERM hit the default action. The process then died without writing `-terminated` or emitting the late result the test is meant to reject.
- Reproduced deterministically by inserting a 150ms busy-wait between the two statements: all 4 cancellation tests fail with the CI error. After the fix, the same 150ms gap (now after the ready write) passes 4/4. Note that a gap over 250ms is invalid as an experiment, because the product's SIGKILL escalation (`src/evaluator.js:268`) fires first.

## Fix
- Swapped the two statements in the fixture so the handler is installed before readiness is announced, with a short comment. No product code changed and no assertions were relaxed.
