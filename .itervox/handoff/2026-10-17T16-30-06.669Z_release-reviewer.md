## Assessment against the acceptance criteria
- **Frozen totals:** the view uses the checkpoint's recorded base/head (or the pinned `indexEntries`). It refuses to show anything if blob IDs or the path set differ from the snapshot, and consistency with the snapshot's `--no-renames` file list holds for renames. Unknown counts stay `null`, and the UI labels them "n/a" or "without line counts".
- **Privacy:** excluded files appear only as a count. A rename across the exclusion boundary does not leak the excluded name. `/diff` serves only allowed paths. Repository text enters the DOM only through `textContent`.
- **Evidence:** line ranges come only from retained reviewer observations whose blob IDs match. `read_diff` pages are checked byte-for-byte at their offset. Model reason text is never shown. When no location exists, the page says so.
- **Preserving work:** only `#composer` buttons lock. Display-only publishes keep the revision, so an in-flight answer is not rejected. Tests cover the draft surviving three files, filters, context changes and tab switches.
- **Honest claims:** the passed message disclaims full review. Scope is labeled "checkpoint changes", and question evidence is labeled separately from all changes.

## Findings
None blocking.

Non-blocking observations for follow-up:
1. When the reviewer read a whole `read_diff` page, every row of the hunk gets marked (see `02-desktop-answering-evidence.png`), so the marker adds little on small files. This follows from the decision to show only verified reads, and is noted in the PR.
2. On very large repositories, `ls-tree -r` output over 16 MB falls back to an empty map, which shows "no longer matches its recorded Git objects" instead of a size message (`src/change-view.js:132`). The view degrades safely to unavailable, but the message is misleading.
3. Gap rows show unchanged lines before and between hunks, but not after the last hunk.
4. Committing this handoff conflicts with `main`'s `/.itervox/handoff/` ignore rule: the review profile requires it in Git, so it was force-added. An operator should decide which rule wins.
5. Not done, as documented in the PR: split view (optional), pane resizing, and a change view in the terminal and fallback forms.
