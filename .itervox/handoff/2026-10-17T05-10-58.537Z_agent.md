## Mid-worker yolo gap (QA comment on ac27573)
QA showed that turning yolo on while a background worker was inside `store.prepare` still allowed new reviewer
requests 2 and 3, and the worker then recorded `ready` with an active check.
- `src/preparation.js`:
  - The worker's session-store `validate` now checks `yoloStatus(repo.root)` first. That validator runs before
    every reviewer request (`beforeCall`) and before the result is saved, so no new request starts after yolo is
    turned on and the check never becomes `active`.
  - On any failure while yolo is on, the worker finishes `stale`, not `failed`.
  - An explicit yolo check after `store.ensure` closes the "empty pending session" case.
  - Checks this worker ensured but never prepared are passed to `store.discard`.
  - New `generate` option (used only when `runPreparation` builds its own store) lets tests drive the production
    validator with a fake transport.
- `src/sessions.js`: new `discard(id)`. Under the session lock it deletes a check only if it is `pending` with
  0 calls, no questions and no reviewer checkpoint. Any check with progress is kept, so it can be resumed later.
- `src/help.js`: the `sphinx yolo` text says that no *new* model request starts. A request already in progress
  when yolo is turned on may finish; a transport cannot un-send a request that already went out.
- Tests (`test/preparation.test.js`), using the real session store and production validator:
  - yolo turned on during the first request (repo and global): `stale`, exactly 1 request, no active check, and
    the started check is kept with calls=1 and no questions;
  - yolo turned on right after `store.ensure`: `stale`, no requests, no pending checks.
  - Both fail with the guards removed (verified) and pass with them.

## CI flakes fixed (also failing on main)
- `reviewer-recovery` "review deadline reports a readable timeout" (Node 22, "Promise resolution is still pending
  but the event loop has already resolved"). Cause: `AbortSignal.timeout` uses an unref'd timer, so a review
  waiting only on its deadline lets the process exit. Confirmed with a standalone script on Node 20 and Node 24
  (exit 13, "unsettled top-level await").
  - Fix in `src/reviewer.js`: the deadline is now a referenced `setTimeout`, aborting with a `TimeoutError`
    DOMException. `runReviewer` clears it in `finally`.
- `git-continuation` "Unexpected end of JSON input" (pause/cancel/false-success, Skip this time, staging…).
  Cause: the fixture wrote `ready-N.json`, `.decision` and `.approval` with a plain `writeFile` while the other
  process polled and parsed them. All three are now written atomically (tmp file, then rename).
- `reviewer.test.js` "first native or structured request … without a planning call" timed out under full-suite
  load (2.2s against a 2s whole-review deadline). The shared test config's `timeoutSeconds` is now 30. The
  deadline tests still set their own sub-second values.
