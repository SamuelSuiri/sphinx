# CRI-45 handoff — yolo pauses background review

## Change
- `src/preparation.js` `planFor`: returns a skip plan when `yoloStatus(repo.root, env)` is active (repo or global).
  - `schedulePreparation` therefore launches no worker and clears `latest.json` (status shows no background review).
  - `runPreparation` re-plans before claiming work and before each `store.ensure`/`store.prepare`, so a job scheduled
    before yolo was enabled finishes `stale` with zero reviewer calls and no pending session.
- `src/help.js`: `sphinx yolo` help now says background review is paused.
- `test/preparation.test.js`: two regression tests (repo + global yolo skip scheduling; yolo enabled after scheduling
  supersedes the worker). Both fail on main and pass with the fix.

## Not changed / follow-ups to surface
- Pending sessions created *before* yolo was turned on still show in `sphinx status` (they are not deleted).
- `src/overrides.js` header comment says "the skipped check stays pending", which contradicts git-gate's
  "straight bypass: no check is created". Stale comment; worth a separate cleanup.
- Turning yolo off does not reschedule preparation by itself; the next commit/checkout hook or `sphinx prepare` does.
- `test/reviewer.test.js` "first native or structured request can finish ... without a planning call" failed once
  under full-suite load and passed on re-run. Looks timing-flaky.
