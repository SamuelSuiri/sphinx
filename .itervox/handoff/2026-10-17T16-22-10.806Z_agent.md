# CRI-49 handoff: CI repair (release controller repair 1/3, ci_failed)

PR: https://github.com/parthh01/sphinx/pull/9. Started from the expected head `f192c53`; `origin/main` had not moved.

## Failure
- ubuntu/24: `test/browser-interview.test.js` "the page serves the frozen change and verified question evidence…" saw `phase: 'waiting'` and `change: undefined`. ubuntu/22 was cancelled by fail-fast.
- Root cause (test-only): the test built its env as `{ ...process.env, … }`. GitHub Actions sets `CI=true`, and `createBrowserInterview` deliberately returns `unavailable` under `CI` (covered by the existing "CI and evaluator subprocesses never start a browser or model" test). The questionnaire therefore never started on CI.
- Reproduced locally with `CI=true node --test --test-name-pattern="frozen change" test/browser-interview.test.js`.

## Fix
- The test now passes a minimal env (`PATH`, a temporary `HOME`, `SPHINX_HOME`, `SPHINX_USER_HOME`, Git config isolation), so the runner's environment no longer leaks in. No product code changed and no assertions were relaxed.

## Checks
- `CI=true npm test` (Node 24.6, macOS): 621/621.
- The targeted test with `CI=true`: passes (failed before the fix).
