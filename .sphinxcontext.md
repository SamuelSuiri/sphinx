# Sphinx

Sphinx is an open-source Node.js CLI that helps developers retain understanding of code written with coding agents. Git checkpoints require the human to answer bounded questions about observable behavior and design consequences before a protected push proceeds.

The Git hook determines when a check is required. A separate Pi SDK reviewer session investigates immutable Git evidence without the development conversation and generates questions and private rubrics. Pi owns the agent session, tool loop, and native compaction. Sphinx supplies restricted tools, project context, model transports, a bounded archive of exact evidence, and per-request usage accounting. Independent grading uses that evidence and the rubric. Incorrect answers lead to an explanation and a new scenario about the same concept. Native Codex/Claude MCP forms and Pi extension dialogs deliver questions directly to the human. Cursor and OpenCode adapters deterministically open a dedicated Sphinx CLI window for the exact checkpoint on supported desktops and wait for its result. Human answers stay in the questionnaire; the development model receives only status and guidance to retry the original blocked Git operation. Headless or unavailable presentation falls back to a human terminal check.

Core invariants: ignored or sensitive file contents must never be read or sent to a model; background preparation cannot approve code; completion is bound to the exact source, destination, policy, and project context. Preserve existing Git hooks and agent settings. Keep model requests bounded, default routes free, and retries explicit. Small changes need only one initial question.

The implementation is provider-neutral and uses Node.js 22.19+ with @earendil-works/pi-coding-agent and @earendil-works/pi-ai pinned to 1.2.0. Codex and Claude CLI routes remain fresh isolated model transports under Pi, using existing CLI authentication. The Pi development-client extension is separate from the embedded reviewer runtime. Other clients can use the generic Git gate and terminal check. Tests use temporary Git repositories and isolated homes with fixture evaluators. Project setup belongs in .sphinxconfig, .sphinxignore, and this context file; credentials remain outside repositories.
